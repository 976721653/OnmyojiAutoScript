## ADDED Requirements

### Requirement: 文档元信息表格头

每个 `.agents/docs/` 下的文档文件开头 SHALL 包含一个 markdown 表格，记录文档的元信息。表格包含类型、状态、更新日期、标签、摘要字段，可选包含关联字段。

#### Scenario: Agent 通过索引定位文档后判断相关性

- **WHEN** Agent 在 INDEX.md 中找到可能相关的文档后打开文档
- **THEN** 首先看到文档元信息表格头，通过摘要和标签快速确认文档是否与当前任务相关

#### Scenario: 文档元信息表格格式

- **WHEN** 文档包含元信息表格头
- **THEN** 表格格式为：

```markdown
| 属性 | 内容 |
|------|------|
| 类型 | <类型> |
| 状态 | <状态> |
| 更新 | YYYY-MM-DD |
| 标签 | #tag1 #tag2 |
| 摘要 | 一句话描述 |
| 关联 | 可选，链接到其他文档 |
```

表格与正文之间用 `---` 分隔线隔开

---

### Requirement: 文档类型分类

文档 SHALL 按 `docs/` 下的子目录分类。目录使用英文命名以避免编码和跨平台问题，类型字段使用中文以便阅读。对应关系：

| 目录名 | 类型字段值 |
|--------|-----------|
| dev-logs | 开发日志 |
| knowledge | 知识库 |
| pitfalls | 常见场景 |
| rules | 规范 |

#### Scenario: 文档放入正确目录

- **WHEN** 创建新文档时
- **THEN** 文档放入对应的英文子目录（知识库类型 → `docs/knowledge/`，规范类型 → `docs/rules/`）

---

### Requirement: 文档状态生命周期

文档元信息中的"状态"字段 SHALL 取值为 `草稿`、`已验证` 或 `待更新`。新建文档默认为 `草稿`，经评审确认后标记为 `已验证`，内容过时后标记为 `待更新`。

#### Scenario: 文档状态流转

- **WHEN** 文档内容发生变化或经过验证
- **THEN** 状态字段按 草稿 → 已验证 → 待更新 流转，Agent 优先信任状态为 `已验证` 的文档

---

### Requirement: 文档摘要字段

文档元信息的"摘要"字段 SHALL 用一句话概括文档核心内容，篇幅不超过 80 字。摘要面向 Agent 索引判断，需包含足够信息让 Agent 判断是否值得打开全文。

#### Scenario: INDEX.md 引用文档摘要

- **WHEN** INDEX.md 的表格中列出文档条目
- **THEN** 每个文档条目包含该文档的摘要字段内容，Agent 无需打开文档即可做出相关性判断
